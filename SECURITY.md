# Безопасность

## Безопасность мобильных клиентов

Для Android используем системный `VpnService`, для iOS — расширение
`NEPacketTunnelProvider`. Мобильные клиенты должны передавать пакеты ядру
через системный интерфейс и вызывать Go-код через нативные привязки.
Подключение не должно открывать локальный HTTP, SOCKS или порт управления
ни на loopback, ни в локальной сети. Перед выпуском проверяем это на
устройствах при подключении, переподключении и отключении.

Запрашиваем только разрешения, нужные для работы VPN. Универсальное
разрешение Android `QUERY_ALL_PACKAGES` клиенту не требуется. В журналах и
телеметрии не должно быть посещённых сайтов, списка установленных
приложений, адресов подписок и ключей. Для локального хранения секретов
используем iOS Keychain и шифрование с ключом из Android Keystore.

Операционная система сообщает о системном VPN штатными средствами.
Например, Android предоставляет признак `TRANSPORT_VPN`.

Для публикации в магазинах указываем назначение VPN и обработку данных
до первого подключения. Перед выпуском сверяем требования
[Google Play к VpnService](https://support.google.com/googleplay/android-developer/answer/16558241)
и [App Store к VPN-приложениям](https://developer.apple.com/app-store/review/guidelines/#vpn-apps).
